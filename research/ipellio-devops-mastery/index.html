💡 Sự Khác Biệt Giữa "Backend Developer" Và "DevOps Engineer"

Khi còn ở tư duy Backend thuần túy, bạn thường giả định: "Network luôn thông suốt, RAM luôn vô hạn, database luôn sẵn sàng và tiến trình Uvicorn không bao giờ bị hệ điều hành tiêu diệt."
Khi chuyển sang vai trò DevOps, bạn suy nghĩ theo nguyên tắc **Phòng Thủ Thực Tế (Defensive Operations)**:

1. Phân Vùng Lỗi (Blast Radius)

Nếu Celery worker bị tràn RAM do task nặng, nó có làm sập luôn FastAPI không? Tại sao phải gán cờ cgroup RAM limit?

2. Tính Bất Biến (Immutability)

Không bao giờ SSH vào server để sửa code hay gõ pip install thủ công! Mọi thay đổi phải đi qua Git commit -> Docker image -> CI/CD.

3. Đường Thoát Hiểm (Exit Path)

Bất kỳ tính năng mới nào deploy lên cũng phải có kế hoạch Rollback trong 30 giây nếu Alembic fail hoặc API trả về HTTP 500.

🧩 7 Khái Niệm Hạ Tầng Cốt Lõi Bạn Phải Nắm Như Lòng Bàn Tay

1. Reverse Proxy & Ingress Caddy

Caddy đóng vai trò "người gác cổng" duy nhất đón traffic port 80/443. Nó đọc Host Header (`api.ipellio.com` hay `workspace.ipellio.com`) để chuyển tiếp nội bộ tới đúng container cổng 8000 hoặc 3000.

2. Docker Bridge Network Network Isolation

Các container nói chuyện với nhau bằng tên (`http://api-gateway:8000`, `redis://redis:6379`) nhờ Docker DNS nội bộ. KHÔNG container nào (trừ Caddy) mở port ra Internet, tạo lá chắn phòng thủ 100%.

3. Multi-Queue Worker Celery Concurrency

Worker phân chia lắng nghe các hàng đợi: `sync` (đồng bộ dữ liệu dài hạn) và `workspace_abn` (tra cứu ABN tức thì). Điều này ngăn các task nặng làm nghẽn task người dùng đang đợi.

4. Memory Eviction Policy Redis 7

Redis bị giới hạn cứng 256MB. Với cờ maxmemory-policy volatile-lru, khi chạm trần, Redis tự xóa cache hết hạn lâu nhất thay vì quăng lỗi crash sập ứng dụng.

5. Postgres Advisory Lock Database Locks

Lock logic cấp ứng dụng được quản lý ngay trong PostgreSQL bằng pg_try_advisory_lock(key). Giúp đảm bảo job đồng bộ IP Australia không bao giờ chạy đè lên nhau kể cả khi trigger 2 lần.

6. Atomic Rollback Anchor CI/CD Safety

Trước khi kéo image mới, GitHub Actions lưu ID sha256 của image đang chạy khỏe mạnh. Nếu smoke test fail, nó tự động re-tag và khởi động lại image cũ chỉ trong vài giây.

🌊 Hành Trình Của 1 HTTP Request Từ Khách Hàng Đến Cơ Sở Dữ Liệu

Theo dõi từng mili-giây và từng trạm dừng chân của một gói tin HTTPS khi người dùng truy cập hoặc gọi API.

1
Cloudflare Edge — Tường Lửa & Chấm Dứt SSL Công Khai < 15ms

Client gửi request tới https://api.ipellio.com/api/v1/search. Cloudflare giải mã DNS, kiểm tra WAF (chặn SQLi, XSS, bot xấu), giải mã TLS và thiết lập kết nối an toàn tới IP Lightsail.

SSL Mode: Full (Strict) • TLS 1.3 • HTTP/2 Multiplexing
2
Caddy Reverse Proxy (Lightsail :443 / :80) < 2ms

Caddy tiếp nhận request, đọc Host Header api.ipellio.com, thêm các header chuẩn: X-Real-IP, X-Forwarded-For và đẩy vào Docker internal network tới http://api-gateway:8000.

3
FastAPI Core Gateway (Uvicorn ASGI) 10ms - 50ms

Uvicorn worker tiếp nhận request, Pydantic parse schema & validate payload. Kiểm tra cache trong redis://redis:6379/1. Nếu cache miss, lấy connection từ asyncpg pool query PostgreSQL RDS.

4
AWS RDS PostgreSQL 16 (Sydney Private Subnet) 5ms - 25ms

Thực thi câu lệnh SQL với index pgvector / btree. Dữ liệu được mã hóa KMS tại đĩa cứng EBS. Trả kết quả về FastAPI -> Ghi cache vào Redis -> Caddy trả HTTP 200 về Client.

5
Nhánh Bất Đồng Bộ (Background Task): Celery & Redis Async Background

Nếu request cần xử lý nặng (ví dụ: tạo file PDF báo cáo nhãn hiệu hoặc tra cứu ABN): FastAPI đẩy task message vào Redis DB 0. Celery worker nhận job, xử lý ngầm và lưu trạng thái vào database. Người dùng nhận response ngay lập tức mà không phải chờ đợi!

Limit: 128M / Res: 64M
Vai trò: Ingress Gateway, chấm dứt SSL, định tuyến subdomain tới các container nội bộ.
ports: ["80:80", "443:443"]
command: caddy run --config /etc/caddy/Caddyfile
api-gateway
Limit: 1024M / Res: 384M
Vai trò: FastAPI Core Application, phục vụ REST API, quản lý auth JWT, tương tác PostgreSQL & Redis.
command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2 --proxy-headers
celery-worker
Limit: 768M / Res: 256M
Vai trò: Xử lý tác vụ ngầm. Lắng nghe queues: sync và workspace_abn.
command: celery -A app.core.celery_app worker -l info -Q sync,workspace_abn -c 2 --max-tasks-per-child=50
redis
Limit: 256M / Res: 128M
Vai trò: In-memory Broker (DB0), Cache (DB1) và Distributed Locks (DB2).
command: redis-server --maxmemory 256mb --maxmemory-policy volatile-lru
sync-beat
Limit: 256M / Res: 128M
Vai trò: Bắn event theo lịch cron định kỳ vào hàng đợi Redis để worker thực thi.
command: celery -A app.core.celery_app beat -l info
workspace / admin
Limit: 512M / Res: 256M
Vai trò: Next.js App Router standalone node server, phục vụ SSR và client web UI.
command: node apps/workspace/server.js (port 3000 nội bộ)

🚨 Sổ Tay Khắc Phục Sự Cố Khẩn Cấp (Troubleshooting Runbook)

Khi hệ thống gặp lỗi hoặc có alert báo sập, tra cứu ngay tại đây:

🔴 Sự cố 1: Container đột ngột biến mất — Exit Code 137 (OOMKilled)

Mức độ: Nghiêm trọng

Nguyên nhân: Exit code 137 = 128 + 9 (SIGKILL). Linux Kernel Out-Of-Memory Killer đã cưỡng chế hạ sát tiến trình vì vượt quá giới hạn RAM cho phép.

# 1. Kiểm tra log của kernel để xác nhận OOM:
dmesg -T | grep -i oom
# 2. Kiểm tra bộ nhớ Swap của máy chủ:
free -m
# 3. Tạo ngay swapfile 2GB nếu Swap đang bằng 0 (giải cứu tức thì):
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile

🟠 Sự cố 2: Caddy Báo Lỗi "502 Bad Gateway"

Mức độ: Cao

Nguyên nhân: Caddy vẫn hoạt động tốt nhưng không thể kết nối tới container backend (FastAPI chưa kịp start xong, bị crash vòng lặp hoặc bind sai port).

# 1. Kiểm tra xem container api-gateway có đang chạy không:
docker compose ps api-gateway
# 2. Xem 100 dòng log gần nhất để tìm lỗi cú pháp hoặc database error:
docker compose logs -n 100 --no-log-prefix api-gateway
# 3. Test trực tiếp endpoint nội bộ bằng curl:
curl -I http://localhost:8000/api/health

🟣 Sự cố 3: Database Alembic Migration Bị Treo Cứng (Table Lock)

Mức độ: Nghiêm trọng

Nguyên nhân: Migration chạy lệnh ALTER TABLE trên bảng đang có query SELECT/UPDATE chạy ngầm kéo dài, dẫn đến Postgres giữ AccessExclusiveLock làm nghẽn toàn bộ request mới.

-- Kết nối psql vào RDS và tìm query đang chiếm lock:
SELECT pid, age(clock_timestamp(), query_start), state, query FROM pg_stat_activity WHERE state != 'idle';
-- Cưỡng chế ngắt transaction đang chặn đường (thay pid thực tế):
SELECT pg_terminate_backend(12345);

🔵 Sự cố 4: Redis Báo Lỗi "OOM command not allowed when used memory > 'maxmemory'"

Mức độ: Cao

Nguyên nhân: Redis chạm trần 256MB và chính sách eviction chưa kích hoạt, từ chối mọi lệnh ghi từ Celery.

# Bật chính sách dọn dẹp LRU nóng ngay lập tức trên Redis đang chạy:
docker compose exec redis redis-cli CONFIG SET maxmemory-policy volatile-lru
